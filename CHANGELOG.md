# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.1.0] - 2026-10-08

### Fixed

- Framework mappings reach the output. The registry's `frameworks` object was never deserialised, so every finding's `framework_mappings` serialised as `{}`; the registry loader now reads it and the engine attaches the mappings to each finding after a module runs.
- Severity honours the registry. `impactRating.severity` is used when `controls/risk-severity.json` has no override (previously everything without an override was `Medium`).
- Registry names and CIS references describe what the code tests. 53 entries whose name or `cis-m365-v6` reference described a different control than the module implemented were corrected (identity admin/CA/app checks, SharePoint sharing, Forms, Defender anti-spam/malware/ZAP, DLP and labels, Purview retention, Power BI, Exchange authentication and audit).
- Bogus `cis-m365-v6` values that were not CIS Microsoft 365 numbers (`4.x`, `5.2`–`5.4`, `6.1`–`6.4`, `7.4`, `8.1`–`8.3`) were removed or moved to the right recommendation; clashes resolved (1.1.2 now on `ENTRA-BREAKGLASS-001` only, 1.1.4 on `ENTRA-CLOUDADMIN-002` only, 4.2 removed from `EXO-ANTIPHISH-001`, 5.1.2.1 removed from `CA-EXCLUSION-001` and `ENTRA-SECDEFAULT-002`). One NIST CSF 1.1 id (`PR.AC-1`) replaced with its CSF 2.0 equivalent.
- Check ids in the registry follow the code: `INTUNE-MAA-001` → `INTUNE-MULTIAPPROVAL-001`, `INTUNE-WIPEAUDIT-001` → `INTUNE-WIPAUDIT-001` (the code id carries the typo; renaming both later is a follow-up), `PBI-*` folded into the `POWERBI-*` entries the module emits (`PBI-TENANT-*` → `POWERBI-TENANT-*`), `EXO-DKIM-001` dropped in favour of `DNS-DKIM-001`.
- Checks that cannot run now report `Unknown` with the reason instead of being dropped from the results (`Finding::unknown`, `modules::record`).

### Added

- `cis-m365-v7` framework key on every check that has a `cis-m365-v6` reference (128 checks), plus `controls/frameworks/cis-m365-v7.json` and the loader entry for it. Numbers shared with v6 were verified against the published v7 titles; the remainder are carried over from v6 numbering.
- Registry entries for the 30 check ids the modules already emitted but the registry never defined: `INTUNE-CONFIG/DEVICES/SCOPETAGS/SETTINGS-001`, `INV-*`, `LIC-*`, `SOC2-*`, `VALUE-*`.
- Registry overlays: `controls/registry.d/*.json` files are merged over `controls/registry.json` in file-name order, so modules can ship their new checks without editing the base file.
- `azure` module (default) reading Azure Resource Manager, Defender for Cloud, Sentinel and Power Platform through the Junction gateway (`src/junction.rs`, `controls/junction-catalog.json`, `scripts/junction-catalog.py`).
- Resource token exchange for Exchange Online, Azure Resource Manager, SharePoint admin, Teams admin, Defender for Endpoint and Power Platform (`auth::Resource`), with SharePoint CSOM and Teams admin clients under `src/clients/`.
- Graph scopes for Purview, PIM, access reviews, enrolment, backup, identity protection, audit log query and threat hunting.
- JSON report schema 1.1: `schema_version` and `tool { name, version }` at the top level, populated `framework_mappings` on findings (`cis`, `cis_v7`, `nist`, `nist_csf`, `iso27001`, `soc2`, `hipaa`, `pci_dss`, `cmmc`, `cisa_scuba`, `fedramp`, `essential_eight`, `mitre_attack`, `other`).
- CSV columns for CIS M365 v7, CIS M365 v6, NIST CSF 2.0 and Essential Eight; HTML report shows framework references per finding, Unknown and Not Licensed counts, and a fixed section order.
- `tests/registry_consistency.rs`: every emitted check id must be defined, every registry check marked automated must be emitted, ids and entries must be well formed.
- `docs/CHECKS.md`, generated by `scripts/checks-table.py`.
- GitHub Actions CI (`fmt`, `build`, `test`, `clippy`, JSON validation).

### Changed

- `hasAutomatedCheck` is `false` on registry checks no module emits (see `docs/CHECKS.md` for the current list); it was `true` on 109 unimplemented entries.
- `controls/risk-severity.json` keeps only the 156 entries that differ from the registry severity; 38 duplicates removed.
- README rewritten around the current modules, the resources beyond Graph and what each needs, the Graph scope list, status semantics, the JSON schema, the Junction catalogue and crownguard import.
- `controls/registry.json` `dataVersion` bumped to `2026-10-08`.

### Removed

- Duplicate `PBI-*` registry entries (11) and `EXO-DKIM-001`.
